# Homework app review — 27 September 2026

Scope: existing exercises, session flow, grading, persistence, reporting, offline operation, and tests. No exercise types or dependencies were added.

## Findings addressed

| Area | Defect and correction |
| --- | --- |
| Startup | Two math generators could produce fewer than four distinct choices and throw during startup. Added valid fallback distractors for prism volume and a vertex at the origin. Both crash cases have deterministic regressions, plus a 300-seed startup sweep. |
| Offline installation | Lazy map data was missing from the install cache, and required question scripts could fail to cache without failing installation. The complete required question set must now cache successfully; map data remains lazy to execute. |
| Updates | Fresh HTML could load against older cached scripts. Navigation now uses the installed version until update activation. First installation no longer reloads an open quiz; subsequent activation checkpoints each tab before reload. Initialization after page load also registers offline support. |
| Unsubmitted answers | Save & Exit discarded typed values, drag placements, matching lines, selections, and command sequences. A bounded pending-answer field now survives checkpoints and rendering without grading the draft. Old checkpoints remain compatible. |
| Completed sessions | Reviewing completed work could recreate a resumable checkpoint. Completed rounds no longer save or validate as unfinished sessions; exiting review returns to the start screen. |
| Loading races | Learners/settings could change during startup, and a delayed resume could overwrite another session. A shared loading lock preserves control states and prevents overlapping start/resume operations. |
| Numeric grading | Inputs such as `1 2` or `12'3` were silently combined into a number. Only consistent, valid thousands grouping is removed; fractions and supported regional formats remain accepted. |
| Answer timing | Time reviewing earlier questions counted as response time for the current question. Returning to an unanswered question starts a fresh timing interval. |
| Reporting | An immediate `missing`/`processing` acknowledgement could strand a report. Status checks now retry with bounded delays without reposting the session. |
| Reporting storage | Failed queue writes lost reports, while failed removal writes could repeatedly resend confirmed reports. An in-memory fallback retains pending reports while the page is open; confirmed IDs prevent a resend loop. |
| Legacy report totals | An absent optional graded-question count became zero in Apps Script. Missing values now fall back to the session total, while an explicit zero stays zero. |
| Saved history | Normalization stripped choice options from records and exports. Options are now bounded, preserved, and displayed in history. Failed history deletion reports failure visibly. Failed history saving at completion retains results in memory and asks the parent to keep them open. |

## Verification

`npm run qa:all` now includes the existing generation/content checks, 19 focused lifecycle regression tests, browser smoke checks, and the expanded desktop/mobile/offline/update matrix. GitHub Actions includes the release browser matrix too.

The browser matrix covers interrupted answers across input and interactive modes, malformed storage, failed history writes, delayed startup/resume, first-use offline maps, and a real service-worker update during an unfinished answer. Reporting tests use local substitutes; no test results are submitted to the deployed receiver.

Final verification: `npm run qa:all` exited successfully after the independent review fixes. All 19 new regression tests passed; the startup test covers 300 seeds. Existing QA generated 8,200 questions, checked 8,600 grade-alignment samples and 6,150 content-quality samples, and validated 1,000 time plus 1,000 probability questions. Both browser suites passed. `git diff --check` also passed. Independent rereview found no remaining Critical/Important issues.

## Deployment and limits

- Changes are local and uncommitted. The existing deletion of `docs/IMPLEMENTATION_PROGRESS.md` was preserved.
- The Apps Script receiver change must be copied into the bound project and redeployed using the existing [receiver deployment instructions](README.md#google-sheets-results-reporting). Editing the repository does not update the live receiver.
- If browser storage is unavailable, the reporting fallback lasts only while the page remains open. Durable offline recovery still requires writable browser storage.
- Existing content QA reports advisory answer-length cues. These are separate from the content-quality gate; editorial rewriting and new exercises are outside this maintenance pass.
- Browser verification uses installed Chromium. Physical iOS/Android devices and the live Google receiver were not exercised.
